验证日期：2026-09-13（北京时间）。本次为有限样本、公开只读请求的技术验证，不是生产接口稳定性验收。

## 结论

基金目录、历史净值及部分公开费率可以获取，足以开始工程初始化和只读基金浏览开发。**尚未证明能完整获取支付宝在售基金，也未完成模拟交易所需的规则验收。阶段 0 只完成数据可访问性和样本一致性部分。**

本次未登录支付宝、未使用真实账户、未执行买卖、未写入项目数据库。没有绕过认证或限流。

## 对实现有影响的发现

1. **历史状态和当前页面状态不能混用。** 000147、110011 的历史净值申购状态与当前东方财富页面展示不同。两者日期和渠道含义可能不同，不能认定同一时刻谁错，也不能据此推断支付宝允许买入。
2. **C 类不能统一视为免手续费。** 本次官网样本 000148 无申购费，但持有不足 7 天的赎回费率为 1.50%，7～29 天为 0.75%。费率必须按具体份额类别和持有期限记录，官网标准费率也不能冒充支付宝优惠费率。
3. **宽泛分类不足以决定支持范围。** 110011 官网大类是混合型，但名称与投资范围涉及 QDII。首版需进一步核验产品子类型；本次名称检测只是排除样例，不是完整分类器。
4. **交易日不能只排除周末。** 例如 2026 年 9 月 25 日周五休市，9 月 28 日恢复交易；政府调休上班日也不一定开市。依据：[上交所 2026 年休市通知](https://www.sse.com.cn/disclosure/announcement/general/c/c_20251222_10802507.shtml)。
5. **净值接口不提供完整结算规则。** 截止时间、确认日、到账日、最小金额、最低剩余份额、持有天数起止和取整方式，需要继续从有效合同及渠道规则核验。不得统一硬编码“所有基金 T+1 确认、T+2 到账”。

## 后续开发与验收门槛

可以立即开始：前后端骨架、数据库迁移、登录注册、只读基金搜索和详情。同步数据需按来源保存抓取时间，使用 Decimal 存储/计算净值，保留历史修订线索。

开放模拟买卖之前，逐只建立有来源与生效日期的规则清单，完成以下验收：

| 待完成项 | 验收方式 |
| --- | --- |
| 支持清单和渠道口径 | 区分“公开基金模拟”与“已核验支付宝在售”；未核验不打支付宝在售标记 |
| 申赎费率、最低金额、取整与份额规则 | 从有效合同/产品资料记录规则，制作人工算例并自动核对 |
| 开放日、截止时间、确认和到账 | 核验工作日截止前后、周末、节假日、暂停申赎样例 |
| 分红、转型、拆分等历史事件 | 获得事件日期和处理规则；未支持事件必须阻止错误结算 |
| 缺失数据与重复结算 | 缺净值等待补齐；重跑不重复扣钱/加份额；离线恢复后补结算 |
| 数据源持续可用性 | 增量同步、失败退避、修订检测；另行评估公开部署的数据使用条件 |

交易规则未完成核验的基金只能浏览。首版建议先完成 5 只候选的规则，不以“完整支付宝全量覆盖”为启动条件。

## 复现

在仓库根目录运行（Python 标准库，无新增第三方依赖）：

```powershell
conda run -n simulate-alipay python -X utf8 scripts/verify_fund_sources.py
conda run -n simulate-alipay python -X utf8 scripts/verify_fund_sources.py --offline --output .local/fund-source-validation/offline-report.json
conda run -n simulate-alipay python -X utf8 -m unittest discover -s scripts -p test_fund_sources.py
```

离线复现需要先在本机运行一次在线探测，原始缓存不提交 Git。离线模式验证缓存 URL 和哈希，不代表再次访问了上游。在线默认每次请求至少间隔一秒、超时 20 秒、单响应最多 10 MB；失败返回非零退出码。

首次在线结果见 [JSON 验证快照](../data/validation/fund-source-snapshot-2026-09-13.json)。快照保存小量事实字段及证据元数据，不作为应用实时行情或交易配置。
