### 自选隔离

`POST /api/watchlist/{code}` 接收 `{ "enabled": true/false }`。归属仅由会话确定，禁止额外的 user_id 等请求体字段。数据库联合主键及 on-conflict 保证重复添加幂等，取消只删除当前用户的行。

游客可浏览基金；查看自己的自选或修改自选必须登录。会话过期返回登录提示；请求失败可重试，不把失败操作提前显示为成功。发现页与详情页均可添加 / 取消自选，刷新后保留。

## 数据同步

目前限定此前验证过的 5 只易方达基金：000147、000148、007339、110020、110009。不是支付宝全量在售目录，也不开放 QDII 或未经验证的其他基金。

首次同步抓取约 400 个自然日的历史；之后从最近缓存日期回溯 14 天增量核对。`--full` 可补齐全部历史。每页使用已验证的 20 条来源分页，校验声明总数、页面条数、跨页顺序、重复日期、正数及 8 位小数精度，并与官网重叠日期交叉核对。

同步不随浏览网页发起，不在启动时隐式请求上游。页面“刷新数据”只重新读取本机数据库。数据库即浏览接口的持久缓存，上游不可用时仍能查看此前正确数据与最后更新时间。

### 运行命令

在仓库根目录，先升级迁移并确保已有基础样本：

```powershell
conda run -n simulate-alipay python -m alembic -c backend/alembic.ini upgrade head
conda run -n simulate-alipay --cwd backend python -m app.seed

# 首次约一年历史；已有数据时增量更新全部 5 只
conda run -n simulate-alipay --cwd backend python -X utf8 -m app.sync_funds

# 指定基金
conda run -n simulate-alipay --cwd backend python -X utf8 -m app.sync_funds --codes 000147 000148

# 补齐来源全部历史，需要更多请求和时间
conda run -n simulate-alipay --cwd backend python -X utf8 -m app.sync_funds --codes 000147 --full
```

同步各基金时用 PostgreSQL 事务级 advisory lock 防止不同进程同时写入；不会锁住只读浏览请求。每次请求至少间隔约 1 秒，连接超时 20 秒，单响应上限 10 MB。临时网络 / 5xx 错误最多尝试 3 次并退避；429 停止本次同步，保留已有数据，稍后由维护者重试。

已存在净值出现数值变化时，整只基金本次更新不落库，记录 conflict、旧值、新值及原始证据，保留原净值。解析失败、分页不一致、身份核对失败同样保留旧数据；不删除本地历史来迎合来源变化。确认修订后需另行制定人工修订流程，本期没有无鉴权维护写接口。

### 存储与证据

迁移 `fd20260913`：

| 表 / 字段 | 用途 |

重新运行 seed 仅补不存在的费率快照，不覆盖在线同步数据；原始解析函数由验证脚本和应用共用，不执行来源 JavaScript。

## 接口

| 接口 | 参数 / 返回 |
| --- | --- |
| GET /api/funds | q、category=all/bond/index/mixed、sort=code/name/nav_desc/change_desc/change_asc、watchlist、page、page_size（上限 100） |
| GET /api/funds/{code} | 基本信息、净值摘要、自选状态、费率来源和缺口 |
| GET /api/funds/{code}/nav | period=1m/3m/1y/all；时间序列、完整性、单位净值涨跌及口径 |
| POST /api/watchlist/{code} | enabled；须登录及来源校验头 X-Fund-Lab: 1 |
| GET /api/data/sync-runs | 最近 20 条同步摘要；不返回原始文件路径或用户数据 |

所有金额和净值以十进制字符串返回。基金接口带用户自选状态，响应使用 no-store，避免跨用户共享浏览器缓存。当前目录有意限定小规模池，列表采用批量读取后排序；大规模扩容应先将区间指标和分页移到数据库查询 / 预聚合。
