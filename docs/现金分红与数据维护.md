# 现金分红与数据维护

本阶段在 000147 的模拟买卖闭环上增加现金分红权益和后台数据更新。数据库迁移为 `bac0bcf6b651`。红利再投资、份额拆分、渠道实际到账时间仍未实现；本阶段不扩大可交易基金池。

## 来源与模拟规则

[易方达 000147 官网](https://www.efunds.com.cn/fund/000147.shtml)的分红表包含登记日、基准日、每份金额及发放日，**不含除息日**。同步只创建 `observed` 候选，不能把基准日当成除息日，也不能仅由净值下降推断分红。

登记日的申赎归属参考基金管理人发布的[2021 年 4 月分红公告（邮储银行销售机构公开披露）](https://www.psbc.com/cn/grfw/tzlc/jj/jjcpgg/202104/t20210416_89068.html)：登记日申购不参与，登记日赎回参与。每个新事件仍需核验其公告及适用范围，再录入除息日和来源摘要。历史公告不自动充当未来事件的核验依据。

`cash-simulation-v1` 明确约定：全部使用现金分红；小额红利仍发现金，不模拟小额自动转投；每账户每事件合并参与份额后四舍五入到分；公告发放日用作模拟到账日。这不是支付宝渠道到账承诺。不适用上述归属规则的公告，不得套用本配置。

## 权益与账本

- 用原始买入批次减去登记日前有效赎回份额重建登记日持仓。登记日买入排除，登记日卖出仍包括；已清仓的历史批次也保留权益。申请赎回的冻结份额并不等同于已失去分红权。
- 登记日前的买卖仍待确认时，等待其结算后再计算分红，避免漏发或多发。启动时先处理买入、再处理权益、最后处理赎回；依赖未完成时下一轮补处理。
- 公告核验通过，且正式除息日净值已入库后，创建唯一的账户权益记录及来源、政策、批次快照。
- 发放日前，权益金额计入“红利待到账”，不能用于买入；到账时在同一事务内增加现金、写入唯一资金流水并标记已到账。并发任务通过账户锁串行执行，重复任务不会重复发放。
- 总资产 = 可用现金 + 买入在途 + 赎回在途 + 红利待到账 + 剩余持仓市值。
- 累计收益 = 总资产 − 初始本金；已实现收益 = 赎回净额 − 已结转成本 + 已登记现金红利；持仓净值收益 = 剩余市值 − 剩余成本。分红不冲减原始买入成本。
- 公告金额或发放日被修订时保留原记录和冲突证据，停止该事件后续处理，不自动重算历史流水。未知份额事件、缺净值及未核验公告继续阻止相关收益展示和赎回；不会被一个已核验现金事件掩盖。

## 本机使用

从项目根目录，在项目 Python 环境执行：

```powershell
python -m alembic -c backend/alembic.ini upgrade head
python -m backend.app.sync_funds --codes 000147
python -m backend.app.dividends --list
```

新公告核验后准备 JSON 文件（下列日期和金额只是结构示例，不可作为真实公告导入）：

```json
{
  "fund_code": "000147",
  "record_date": "2026-09-21",
  "ex_date": "2026-09-21",
  "pay_date": "2026-09-23",
  "cash_per_share": "0.01",
  "source_url": "https://www.efunds.com.cn/实际公告地址",
  "source_excerpt": "记录核验的 A 类金额、日期和申赎归属；此处须替换为实际公告的核验摘要。",
  "policy": "cash-simulation-v1"
}
```

```powershell
python -m backend.app.dividends 公告.json
```

只有与已同步官网候选的基金代码、登记日、金额及发放日一致时才可核验。已核验事件只允许完全相同的重放；冲突不能用导入命令覆盖。导入不立刻发钱，结算任务按日期和净值条件处理。冲突处理仍需逐笔人工对账，本阶段没有自动冲正工具。

重启 API 后，000147 每 6 小时检查一次增量更新；常规失败等待 15 分钟重试；来源修订冲突保留日志，正常周期继续核对。已登录用户可在发现页点击“更新 000147 数据”，5 分钟内不重复发起新任务。请求写入数据库，关机不假装持续运行；重启后处理排队任务，异常中断的运行任务在 15 分钟后重试。后台使用独立连接的 PostgreSQL 会话锁，多个 API 进程不重复抓取。

同步仍保留原始响应和哈希、交叉核对官网净值、14 日重叠窗口、增量去重和限速重试。已存在的分红注释不得被空值或不同内容静默覆盖。费用变化或异常同步不会自动重新开放买入；需要按既有启用流程重新核验。

其他 4 只展示基金仍通过现有 CLI 更新。自动更新不是自动核验分红公告，也不自动接入停牌、折扣或特殊权益规则。

## 页面与接口

- 发现页：在线更新、排队/运行/失败反馈、完成后刷新缓存；已有更新日志保留。
- 持仓页：待到账红利、含现金分红的累计/已实现收益、现金分红记录与公告链接。
- 我的：现金分红到账资金流水。
- `GET /api/account/dividends`：仅当前账户的权益记录。
- `GET /api/data/update`：公共数据更新状态。
- `POST /api/data/update`：登录和同源写请求保护，排队更新 000147。

## 验证

测试使用事务回滚或隔离基金、账户，禁用 TestClient 后台联网和全账户结算。覆盖登记日申赎、历史清仓补发、待确认订单、现金/应收对账、合并舍入、重复核验、公告修订、未知折算、跨账户隔离、到账回滚、并发重启补发、更新排队/冷却/重试和中断恢复。浏览器通过受控响应检查分红与更新状态，不向真实账户写入演示分红。
