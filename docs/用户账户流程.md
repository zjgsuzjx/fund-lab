# 用户账户流程

## 已实现

- V2 用户名规则：4–20 位 ASCII 字母、数字、下划线，去除首尾空格后转小写；密码 8–128 位，至少含字母和数字，不裁剪密码。
- 注册创建用户、模拟账户、100,000.00 元本金流水和首次会话，同一事务提交。用户名唯一、账户归属唯一、流水事件键唯一；重复或并发注册返回一个成功，其余 409，不重复发钱。响应中断后可直接登录。
- 注册 / 登录成功进入发现页；通过导航进入我的账户。页面显示真实账户余额和初始流水，支持密码显示、确认密码、阅读说明、保持登录、失败提示和重试。
- 修改密码校验旧密码，成功后撤销该用户所有会话并返回登录页。
- 导出交易与备份入口明确标注未开放；持仓和交易未接入。本期不提供任意余额修改接口。

## 安全与会话

密码使用标准库 PBKDF2-HMAC-SHA256，600,000 次迭代、每条密码独立 128 位随机盐，使用恒定时间比较。未知用户名也执行密码计算，登录错误统一返回用户名或密码错误。

浏览器仅存放 256 位随机令牌的 HttpOnly、SameSite=Strict Cookie，Path=/api；HTTPS 请求同时设置 Secure。数据库只存令牌的 SHA-256 摘要，不存明文令牌。普通会话最长 12 小时，Cookie 随浏览器会话；勾选保持登录则有效 30 天。刷新通过 /auth/me 恢复身份，不使用 localStorage 保存身份或令牌。退出删除服务端会话和 Cookie，旧令牌重放失败；登录时替换当前 Cookie 对应的旧会话。过期会话在后续注册 / 登录时清理。

认证和账户响应设为 Cache-Control: no-store。写操作要求 X-Fund-Lab: 1，拒绝 Sec-Fetch-Site: cross-site，不启用跨域 CORS；保护范围包括登录、注册与退出。注册、登录、改密共用每来源 IP 每分钟 30 次的内存限流，超过返回 429 和 Retry-After；退出不受限流影响。适用于当前单进程本机服务，进程重启会清空计数；多实例部署需改用共享限流存储。

所有账户查询从会话中获取用户 ID，无客户端可指定的账户归属。改密请求禁止额外字段；资金流水无修改接口。忘记密码不开放无鉴权重置接口，页面提供本机管理员核验说明。

## 接口

| 方法与路径 | 行为 |
| --- | --- |
| POST /api/auth/register | username、password、remember（可选）；201；已存在 409 |
| POST /api/auth/login | 同上；200；凭据错误 401 |
| GET /api/auth/me | 当前用户 id、username、created_at；未登录 / 过期 401 |
| POST /api/auth/logout | 204，幂等撤销当前会话 |
| GET /api/account | 当前账户 id、available_cash、created_at |
| GET /api/account/ledger | 当前账户流水，金额以十进制字符串返回 |
| POST /api/account/password | current_password、new_password；204，并撤销所有该用户会话 |

数据库迁移 `ac20260913` 新增 users.username、auth_sessions、cash_ledger，保留旧 email 为可空兼容字段。已有基础用户保留数据并赋予 legacy_ + UUID 的内部用户名；这些旧结构数据不自动转成可登录的新用户名，也不补发本金。若实际存在旧用户，需另行核实其迁移要求。回滚发现无邮箱的新用户时主动拒绝，避免丢失账户数据。

## 启动和验证

沿用 README 的 Conda 环境与启动方式；已有数据库只需升级，不重建：

```powershell
conda run -n simulate-alipay python -m alembic -c backend/alembic.ini upgrade head
conda run -n simulate-alipay python -m alembic -c backend/alembic.ini check
conda run -n simulate-alipay --cwd backend python -m pytest -q
npm --prefix frontend run build
```

测试涵盖密码哈希、注册登录、Cookie 属性、刷新恢复、退出令牌重放、过期会话、重复 / 并发注册、事务失败回滚、A/B 读写隔离、改密撤销全部会话、输入和来源校验、限流。常规数据库测试使用外层回滚；并发测试提交独立事务并只清理自身生成的测试用户。

浏览器人工自动化验收：390 px 页面无横向溢出；确认密码错误、注册及发现页跳转、账户 100,000.00 余额与唯一流水、刷新、退出、未登录路由拦截、错误密码、重新登录及持久 Cookie 均通过。截图保存在忽略目录 `.playwright-mcp/account-*.png`。
