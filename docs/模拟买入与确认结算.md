# 模拟买入与确认结算

本阶段将买入试算、资金预留、订单、确认批次和撤单接通。仅使用注册时发放的虚拟本金，无真实支付或基金交易。买入、待确认和订单详情按 `design/v2/03-buy.svg`、`04-pending.svg`、`10-order-detail.svg` 实现；金额、基金名称与日期使用后端真实记录。Figma 在线接口达到额度后，使用项目内同版导出稿校对。

## 规则与范围

首批仅启用 **000147 易方达高等级信用债债券 A** 的 `000147-public-standard-sim-v1` 方案。其他基金只能浏览、自选。这个版本冻结的是本练习室的公开标准费率模拟方案，不承诺支付宝或其他销售渠道的当前费率、实时申购状态、临时限购或暂停公告。

依据：

- [基金公司 2026 年 1 月更新招募说明书](https://cdn.efunds.com.cn/owch/data/bulletin/20260131/易方达高等级信用债债券型证券投资基金更新的招募说明书.pdf)，正文第 26–31 页：未知价、普通投资者标准申购费率、非直销/网上渠道 1 元起购、金额及份额保留两位四舍五入、通常 T+1 确认。文件发表时间不是本模拟版本生效时间。
- [上交所 2026 年休市安排](https://www.sse.com.cn/disclosure/announcement/general/c/c_20251222_10802507.shtml)：周末及列示休市日期排除，不把调休工作日当成交易日。仅覆盖 2026 年；需要跨入尚未核验的 2027 年确认日期时拒绝新单。

本练习室约定北京时间交易日 **15:00** 截止；其后和休市日申请归属下一交易日。允许在该计价日 15:00 前撤销，恰好到点即不可撤销。以上具体受理/撤销安排属于模拟方案，不冒充实际代销渠道细则。

费用算法使用 `Decimal`：净申购金额 = 买入金额 / (1 + 费率)，四舍五入至分；申购费 = 买入金额 − 净申购金额。固定费档直接扣固定费用。确认份额 = 净申购金额 / 对应 T 日正式单位净值，四舍五入至两位。管理费、托管费不作为订单费用再次扣除。

例如本方案买入 1,000 元：标准费率 0.80%，预计申购费 7.94 元，净申购金额 992.06 元。份额必须等正式净值；不使用昨日净值、盘中估值或随便一条“最新净值”。原型中的 0.10% 和 10 元起购是示例，不能沿用。

## 资金和订单

迁移 `7328c9b86b16` 增加 `buy_orders`、`position_lots`、账户 `reserved_cash`，以及流水的 `available_delta`、`reserved_delta`、`reserved_after`。旧初始本金流水回填可用金额变动，不再发放本金。

| 事件 | 可用资金 | 买入在途 | 已确认批次 |
| --- | --- | --- | --- |
| 提交成功 | 减少买入金额 | 增加买入金额 | 不变 |
| 截止前撤单 | 退回完整金额 | 扣除该笔金额 | 不创建 |
| 确认成功 | 不变 | 扣除该笔金额 | 创建一次，成本含申购费 |

每个事件在同一数据库事务内修改状态、余额、流水与批次。数据库约束防止负余额和重复事件，账户行锁串行化同账户的买入、撤单、结算；基金 advisory lock 与同步任务共享，避免读到同步中间状态。异常事务整体回滚。

请求编号 UUID 在账户内唯一。相同编号和金额/基金重试返回原订单，金额或基金不同返回 409；已确认或已撤销订单也不会因重试被再次创建。前端在发送前保存请求编号到按用户和基金隔离的会话存储；网络结果不明时保留原请求，刷新后重试同一笔。提交时服务端重新检查锁等待后的时间，试算日期或规则版本变化则要求重新确认。

所有账户、订单、流水和持仓查询由服务端会话确定归属，不接受客户端 user_id/account_id。读取、撤单或尝试刷新别人的订单统一返回 404。写请求沿用 `X-Fund-Lab: 1` 来源检查，API 响应禁止缓存。

## 本机运行

在仓库根目录运行（已有环境与 `.env`）：

```powershell
conda run -n simulate-alipay python -m alembic -c backend/alembic.ini upgrade head
conda run -n simulate-alipay python -m backend.app.sync_funds --codes 000147
conda run -n simulate-alipay python -m backend.app.enable_trading
```

启用命令要求已有一次成功同步及新鲜数据，仅开启这一只基金的已审核方案。首次样本导入不会开启交易；同步超过 7 天暂停新买入。同步失败、净值冲突或观察到申购费表变化会关闭买入开关，需要核验并恢复成功同步后重新启用。观察费表不自动覆盖订单内已冻结的规则与费用。

后端启动时自动检查待确认订单，运行期间每 60 秒再次检查。逐单事务处理，重启会补处理。**它只读取数据库，不自动抓取外部净值**：仍须运行净值同步；T+1 已到且指定 T 日正式净值已保存、最近同步无异常才确认。缺净值或同步异常保持在途，不自动退款或虚构失败成交。

可在订单页点击“检查确认结果”，也可运行一次本地结算：

```powershell
conda run -n simulate-alipay python -m backend.app.settle_orders
```

已有订单时禁止直接降级删除交易表；应保留备份并使用前向迁移修复。没有公开的回填日期、设置净值、修改规则或强制成交接口。

## 页面和接口

| 接口 | 功能 |
| --- | --- |
| POST /api/trades/quote | 金额、余额、起购、费率及日期试算，不动资金 |
| POST /api/orders | 请求编号幂等提交买入 |
| GET /api/orders | 当前用户订单，状态筛选、每页 20 笔 |
| GET /api/orders/{id} | 当前订单、冻结规则、计价日、费用、份额及可撤销状态 |
| POST /api/orders/{id}/cancel | 截止前撤单，重复撤单不重复退款 |
| POST /api/orders/{id}/refresh | 仅检查自己订单是否具备确认条件 |
| GET /api/holdings | 当前账户现金、在途、已确认基金和批次 |

前端路由：`#buy/000147`、`#pending/{id}`、`#order/{id}`、`#holdings`、`#orders`。持仓与交易导航已可用，游客先登录；订单页面每 15 秒读取最新状态，失败可重试。账户流水分别显示可用与在途变动，避免把预留/确认显示成再次入账。

发现页总资产包含可用资金、买入在途和已保存净值估算的持仓市值；原“累计收益”位置暂显示买入在途。持仓是本阶段所需的基础查询页，**尚未实现卖出、分红权益、复权收益、订单搜索/日期筛选、CSV 导出**。市值估算及总资产不包含尚未实现的分红权益，页面已注明，不能作为完整投资收益口径。

## 验收记录

- 45 项后端测试通过，其中 24 项为交易场景，覆盖截止前后、节假日、跨年拒绝、费率分界、金额精度、超额买入、规则变化、重复请求、缺净值、提前公布不提前确认、同步冲突、用户隔离、事务失败回滚。
- 使用真实 PostgreSQL 独立连接验证同编号并发、不同编号超额竞争、重复结算、撤单与结算竞争，最终资金/流水/批次一致。测试只清理自建用户、基金及关联数据。
- 浏览器验证真实注册→试算→买入→待确认→刷新→撤单→余额恢复。人为中断已受理订单的响应，再刷新重试，仍只有原来一笔订单。
- 浏览器买入与交易页面在 320 / 390 / 1440 px 下无横向溢出；退出后访问私有交易路由返回登录。截图保存在忽略目录 `.local/trade-*.png`。本次测试账户及其两笔订单已对账后清理。
- 当前真实日期新建的订单等待未来正式净值，不在开发库伪造未来净值来展示成交；确认分支使用事务回滚隔离的测试数据验证。
